最初の記事「税務思考エンジンを作っています」から、9か月近く経ちました。

今はGemini Notebook（旧NotebookLM）を使っていません。代わりに、Pythonで「MCPサーバー」を作っています。 MCP（Model Context Protocol）は、AI（この記事では、大規模言語モデルのことをAIといいます）を外部のWebサイトやデータなどにつなぐための共通の接続方式です。

結果として、一次情報※の収集・整理は随分と楽になりました。

※ この記事でいう「一次情報」は、AIによる要約や解説ではなく、法令や公的機関の資料の原文を指します。

Gemini Notebookとの対話で気づいたこと

Gemini Notebookに資料を読み込ませて対話を続けるうちに気づいたことがあります。 それは、事例として与えていた質疑応答事例のことです。

質疑応答事例は国税庁が公表するものであり、基本的には課税庁側の判断や説明が示されています。 このまま学ばせ続けると、偏った視点になるのではないか？

もちろん、納税者に有利に解釈されている事例もあるので、一概に偏っているとは言えません。

もともと目指していたのは、答えを覚えさせることではなく、その奥にある「考え方」や「視点」を学ばせることでした。 しかし、一方の視点に偏ってAIに学ばせるのは危険ではないか。 AIには一次情報の収集に徹してもらい、疑問点をAIと壁打ちする方が良いのではないか。 そう考えるようになりました。

なぜMCPサーバーを自作したのか

法令などは随時改正されます。 そのため、現時点で施行されている法令、または近い将来に施行される法令に基づいてやり取りをしたいと考えました。

以前作ったアプリ（Streamlit製）でも、現行の法令だけでなく、過去の法令や未施行の法令を取得できました。 ただ、毎回全文を取得させる手間が大変でした。

手順をある程度楽にできないか？そう考えて行き着いたのが、MCPサーバーです。

MCPサーバーにつないだAIと壁打ちをして、納得できないときはGemini Notebookにも聞いてみる。 そうしていた時期もありましたが、現在はGemini Notebookは利用していません。

どちらが優れているかというより、どちらが私にとって「長続きできる」か、「負担が少ない」か。 それを考えて、MCPサーバーを選びました。

MCPサーバーでは、AIが必要なものを必要な分だけ取りに行きます。

  • 法令：e-Gov法令APIから、条文を指定して取得する（全文の取得も可能）。未施行の版があれば知らせる。施行日を指定した取得、版の比較、改正附則（経過措置・適用時期）の確認もできる。
  • 通達：基本通達・措置法通達は項番を指定して取得する。個別通達や事務運営指針も取得できる。
  • 事例・解説：質疑応答事例、タックスアンサー
  • 争いになった事例：訟務重要判例、国税不服審判所の裁決事例

もちろん、通達や裁決事例を法令と同じレベルでは扱いません。それでも、実務上の判断には欠かせないものだと考えています。

MCPサーバーで何が変わったのか

一次情報の収集はAIに任せる

一次情報を探して集める作業は、やはりAIに任せた方が圧倒的に早いです。

壁打ちの結果はノートアプリに残す

AIと壁打ちして得た知識や知見は、ノートアプリに蓄積しています。 このノートアプリにもMCPで接続できるようにしているので、AIはいつでも過去の知見を参照できます。

「3層構造」はやめて、議論の結果を残す

前回の記事で紹介した、知識を3つの層に分けて管理する方法は、結局やめました。

質疑応答事例との差分を見る取り組みは、「ドリル」という形で残しています（今は一旦お休みしています）。

  1. AIに事例の「問」だけを見せる
  2. 条文と通達だけを根拠に、一次回答を作らせる
  3. 国税庁の回答を取得して、足りなかった点、逆に一次回答の方が優れていた点を分析させる
  4. その分析を出発点に議論して、まとまったらノートに残す

カスタムプロンプトに学びを積み上げるのではなく、議論の結果をノートアプリに蓄積するやり方に変わりました。

以前と変わった視点：意思決定を支える情報とは？

一番変わったのは、この視点かもしれません。

意思決定に役立たない情報は思い切って捨てることにしました。 多すぎる情報や判断基準を明確にせずにまとめた情報は、意思決定を阻害します。

どうすれば、疲れた状態であっても、脳にあまり負担をかけずに判断できるか。 何を大事にして判断するか。そこを考えるようになりました。

意思決定には、自分が大事にしている判断基準に気づくことが大切だと考えています。 これは、ご相談を受けるときも同じであると思っています。

条文に触れることの大切さ

AIが一次情報をすぐに持ってきてくれるようになった今、改めて実際の条文に触れることが大事だと感じています。

条文の構造を確認すること。 そして、その法が保護しようとしている取引や事象の射程がどこまでなのかを考えること。

ここは、これからも自分の頭で考えていきたいところです。

同じような取り組みをしている方、関心のある方はお気軽にご連絡ください。

※ AIを利用する際は、実際の相談内容や個人情報をそのまま入力することはありません。必ず事案を抽象化し、個人や法人が特定されない形にした上で検討しています。ノートに残す知見も同様です。
